## Node Lifecycle

`rclpy.init` creates the context, the node owns publishers and subscriptions, and `rclpy.spin` hands control to the executor that dispatches callbacks. Shut down in reverse order.

```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image

class Perception(Node):
    def __init__(self):
        super().__init__("perception")
        self.sub = self.create_subscription(Image, "/camera/image_raw", self.cb, 10)
        self.pub = self.create_publisher(Detections, "/detections", 10)

    def cb(self, msg):
        self.pub.publish(self.to_msg(self.perceive(msg)))

rclpy.init()
node = Perception()
rclpy.spin(node)
node.destroy_node()
rclpy.shutdown()
```

## tf2

Every frame — map, odom, base_link, camera — lives in one transform tree. Ask tf2 for the transform at the image timestamp, not the latest one, or fast motion will smear your detections.

---

## Integration

The vision node publishes measurements; the EKF node subscribes, fuses them with odometry, and publishes the pose and its covariance. Typed messages are the contract between nodes.

<Warning title="Common Misconception">

Creating publishers before `rclpy.init`, or replacing `spin` with a `while True: sleep()` loop — callbacks never fire.

</Warning>
